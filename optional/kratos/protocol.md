# Field Kratos protocol, schema 1

One authenticated loopback TCP connection and one session per owned Python
process. Every frame is a 4-byte unsigned big-endian payload length followed by
one MessagePack map; maximum 64 MiB. The parent binds an ephemeral port, passes
the port as argv and the random token through `FIELD_KRATOS_TOKEN`. The first
request must carry that token. Nothing listens on a non-loopback interface.

## Envelope on every request and reply

| Key | Type / meaning |
| --- | --- |
| `schemaVersion` | integer, exactly 1 |
| `units` | string, exactly `SI:m,kg,s,K` |
| `sessionId` | nonempty string, UUID generated by Field |
| `geometryRevision` | nonnegative int64, monotonic in session |
| `simulationRevision` | nonnegative int64, monotonic in session |
| `requestId` | nonnegative int64, unique in connection |
| `cancelled` | boolean, false for work, true for cancellation |

Requests add `command` and payload keys. Responses echo the envelope exactly and
add `ok`, `obsolete`, plus `data` or `error: {type, message}`. Envelope disagreement
closes the Field connection. A valid structured model error does not kill the
worker. Transport/framing failure does: the caller creates a fresh session.
There is no compression, remote access, multiplexing or automatic retry.

## Commands implemented

- `hello`: import checks, versions, platform, executable, formulation and install
  guidance. Can succeed at the protocol level with `data.available=false`.
- `createBackgroundDomain`: `bounds=[minX,minY,minZ,maxX,maxY,maxZ]`, `resolution`
  in 4..32. Returns background UUID, build count, build timing, and binary
  positions/cells. A second creation in the same session is rejected.
- `solve`: `geometry` is a nested box/union/difference/intersection expression
  with stable IDs, **or** `distance` is a binary float64[nodeCount] block.
  `thermal` contains conductivity, source, boundary_value, penalty. `editClass`
  and `dirtyBounds` carry invalidation intent; the current implementation uses
  full-grid updates/cached analytic distances. Results contain temperature,
  distance, cellState and diagnostics. Explicit setup hooks may inspect request
  metadata (`regions` carries solid/volume/surface/material/BC/output identities) but the reference solver only consumes the documented thermal keys.
- `cancel`: acknowledges cancellation. The serialized worker cannot read this
  while a native solve runs; Field's local revision gate is the authority that
  suppresses obsolete work immediately. Client `cancel()` therefore does not
  wait for a protocol acknowledgement.
- `closeSession`, `shutdown`: release model and terminate the worker normally.
  Field may instead terminate its owned child after a timeout or while closing
  an in-flight solve.

A solve is an atomic snapshot of geometry/material/boundary/solver controls; this
slice intentionally avoids partially applied sequences of `set*` commands.
Creating the worker implicitly creates the session. Bounds/resolution changes
require a new session. Before a solve, both revision components must be at least
the previously submitted components; shutdown and capabilities remain usable
regardless of the last model revision.

## Binary arrays

A response has `arrays=[descriptor,...]` and one `binary` MessagePack bin block.
Each descriptor contains:

```
name: temperature
dtype: float64
shape: [2197]
byteOrder: little
storage: inline
offset: 0
length: 17576
```

`length` and `offset` are bytes. Shape product × dtype width must equal length;
all ranges must lie inside the binary block. Kotlin validates expected names,
shapes, dtypes, endianness, duplicate names, finite floats and connectivity
indices before exposing typed values. Supported dtypes are float64 and int32.
No boxed arrays of vertex/temperature/distance values appear in MessagePack.
Small control vectors such as six domain bounds are ordinary MessagePack arrays.

| Name | Shape | dtype | Lifetime / meaning |
| --- | --- | --- | --- |
| positions | [nodeCount,3] | float64 | returned once, x/y/z metres |
| cells | [cellCount,4] | int32 | returned once, zero-based tetrahedral node indices |
| temperature | [nodeCount] | float64 | result revision, kelvin |
| distance | [nodeCount] | float64 | result revision, positive inside, metres |
| cellState | [cellCount] | int32 | 0 inactive, 1 positive, 2 cut |

For resolution n, node order is x-major, then y, then z, with (n+1)³ nodes.
Each cube is divided into six Freudenthal tetrahedra (all permutations of x/y/z),
consistently positively oriented. Interpolation sorts local cube coordinates to
find that same tetrahedron and uses its four barycentric weights.

All binary storage is owned by the receiver. There are no mapped/shared files
in schema 1. The envelope and array descriptor deliberately permit a future
storage variant, but unknown storage values are rejected rather than guessed.

## Publication and diagnostics

Field increments revisions before queueing a request. Queued obsolete previews
are coalesced. A result can update `latest` only under the revision lock when
its ticket is still current; `withLatest` uses the same lock for rendering.
Explicit cancellation increments the simulation revision. Historical results
remain ordinary data and can be compared deliberately.

Worker diagnostics report model UUID/build count; cut/active counts;
classification, model update, assembly, solve and packing milliseconds; direct
linear residual; extrema and binary bytes. Client diagnostics additionally report
geometry-evaluator time, request serialization/write time, result payload read
time and full round-trip. Result transfer starts after the length header arrives,
so it excludes waiting for the solve but includes local byte-buffer allocation.
The example reports Field visualization submission time. Round-trip includes
computation and transport; submission excludes asynchronous browser painting.
