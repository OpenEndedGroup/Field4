## Learned experiments and measurements

The initial run used:

```sh
uv run --no-project --python /home/marc/temp/comfy/.venv/bin/python python \
  optional/transport-flow/run.py demo --out build/transport-flow --steps 3500 \
  --movie --movie-frames 72 --unsafe-weights
```

The standard portable command is `uv run --project optional/transport-flow python
optional/transport-flow/run.py demo --steps 3500 --movie --movie-frames 72
--unsafe-weights`. It runs the same experiment under the checked-in lockfile.

The shipped two-image model is a width-64, three-hidden-layer SiLU network with
8,770 parameters, target sigma .025, minibatch 256, BSP coupling and seed 17.
It trains only on C/S at movie conditions zero/one. The actual inferred midpoint
and four slices of the time plane were rendered and inspected. Movie colors
remain attached to canonical particle indices.

Static C reconstruction with random/BSP pairing gives sliced W1 .0141/.0136,
path length .545/.357, turning 2.819/.308 radians, and 8-step integration error
.00453/.00035 relative to 128-step RK4. These are illustrative results from one
seed, not a universal claim about coupling strategies.

The density movie contains 16 procedural grayscale targets generated by
`run.target_image(j/15)` and stippled with 4,096 samples each. Starting from its
3,500-step checkpoint, a 16,000-step unregularized fine-tune improved mean density
error .0697 -> .0318, with more movie-motion variation. Two further 8,000-step
branches share this checkpoint, seed, schedule and PyTorch 2.14.1 environment:

```sh
# After saving target_image(j/15) as build/transport-flow/movie-targets/00.png ... 15.png:
uv run --project optional/transport-flow python optional/transport-flow/run.py train \
  --images build/transport-flow/movie-targets/*.png \
  --checkpoint build/transport-flow/short-video.pt --steps 16000 \
  --out build/transport-flow/video-refined
uv run --project optional/transport-flow python optional/transport-flow/run.py train \
  --images build/transport-flow/movie-targets/*.png \
  --checkpoint build/transport-flow/video-refined/transport.pt --steps 8000 \
  --out build/transport-flow/video-control
uv run --project optional/transport-flow python optional/transport-flow/run.py train \
  --images build/transport-flow/movie-targets/*.png \
  --checkpoint build/transport-flow/video-refined/transport.pt --steps 8000 \
  --temporal-strength .002 --out build/transport-flow/video-regularized-locked \
  --movie --movie-frames 96
```

The unregularized/regularized branches give mean trained density error
.0212/.0290 and held-out error .0212/.0284. The 15 held-out conditions are
`(j+.5)/15`; their targets are newly stippled from the procedural function with
seed `901+j`. Mean particle second difference across 17 evenly spaced movie
conditions is .0803/.0519, and largest movie-step displacement .3779/.2472.
The regularized model/video is shipped. Density is still approximate, and movie
identity is mass correspondence, not object tracking or optical flow.

The raw measurements are in `public/docs/assets/stipple_transport/measurements.json`.
Portable two-image and short-video JSON models are supplied; training checkpoints
and sampled fields remain in the ignored `build/transport-flow` directory.
MP4s were decoded into contact sheets and visually inspected. They contain actual
network-deformed particles/grids, not generated illustrations or renderer substitutes.

The published page also shows `source-density.mp4`: the exact 16 grayscale training
images encoded at 4 fps, before stippling or deformation. Regenerated source images
were compared pixel-for-pixel with `build/transport-flow/movie-targets/00.png` through
`15.png`; all matched. The four-second source clip was decoded and visually inspected.
`demo --movie` now exports that source clip and its poster for future comparisons.

FFmpeg video input was separately exercised on a four-condition decode of the
procedural target clip with a five-step tiny training run. This checks the input
pipeline, not learning quality on arbitrary footage.

## Field execution and browser evidence

The editable `examples/stipple_sheet.kt` ran through the repo backdoor on isolated
port 9783, with server-owned headless Playwright. It loaded the actual portable
two-image model, drew a transported particle sheet and lattice, and published
transport/movie/integration-step controls. `field-sheet.png` is the real Field
capture. A second scratch session sent the ordinary browser slider updates to
set transport time .5 and movie time .75; the geometry and displayed readout both
changed, captured in `field-controls.png`.

```sh
uv run --project . --group backdoor python tools/field_backdoor.py --json \
  --with-playwright --port 9783 --timeout 180 \
  --command 'new-box --name StippleSheet' \
  --command 'run @last --file optional/transport-flow/examples/stipple_sheet.kt' \
  --command 'screenshot-box @last public/docs/assets/stipple_transport/field-sheet.png --padding 16'
```

The Field consumer is CPU-only. No native GPU MLP inference, texture-bake consumer,
GPU frame-rate claim, periodic correspondence constraint, or physical tracking
claim has been validated by this work. Field baking exports actual sampled
velocities for a future shader bridge.
