# Field box-code house style

Include this text verbatim in authoring/review prompts, including AI4 prompts. It covers Kotlin/GLSL
boxes, examples, docs and starting places.

- Write for live editing: optimize time to find the creative value, time to feedback, and
  confidence on rerun. Prefer clear names and useful intermediate values to golfing lines.
- Show the lesson's inputs, mappings, loops and decisions. A demo-class call must not hide the
  idea being taught. Retain genuine algorithms, IO and resource ownership behind useful APIs;
  reuse helpers after teaching their implementation. Link retained teaching helpers to their
  class and method in the site's reference.
- Use typed inherited properties, the implicit box receiver and existing Field helpers.
  Prefer these to `fromContext`, reflection or raw property access. `setPropertyRaw` is an
  exceptional escape hatch. Capture required context before asynchronous work.
- Keep GLSL editable in shader properties; use `moduleHere`, `computeModuleHere` or
  `meshModuleHere` for box-owned pipelines. Keep library-owned/per-eye factories explicit.
  Comment shader interfaces with units, packing and coordinate space.
- Use collection literals where supported. Run the real import formatter, ktfmt and GLSL
  formatting. Leave autogenerated preambles alone. Separate preparation, controls, computation,
  output and cleanup with whitespace.
- Keep comments light and accurate: intent, units, assumptions, timing and ownership.
  Explain surprising choices; remove line-by-line narration and obsolete commentary.
- Prefer Markdown for prose/tables and FLines for small drawings. Use HTML/SVG when DOM,
  embedding or that representation is the point.
- Preserve fragment boundaries and declaration semantics. Make resets intentional; avoid
  redundant declaration/reset pairs. Give resources owners and meaningful cache keys.
  Reruns should replace changed resources without freezing editable controls or callbacks.
- Run the exact authored code, check defaults, edit a meaningful value, rerun/reload, and inspect
  real output. Exercise ordinary shader reload. Preserve established results unless asked to
  change them. Compiling alone is insufficient; captures must execute the actual example.

For mechanics and exceptions, see [Box code revision pass](BOX_CODE_REVISION_PASS.md) and the
[agent guide](../../AGENTS.md).

- **Legends over a `three { }` scene are `markdown("""…""", corner = …)`, not `overlay("<div style=…>")`.** The panel is already styled in the viewer's font, folds to its heading, and takes `{bad:…}`-style roles; never set a `font-family`.

For a type that several Kotlin boxes use, prefer a shared Kotlin declarations box. Its code is
ordinary declarations, and `prop<T>` or `@exported` can then pass typed instances between boxes.
See [Connecting boxes](../../public/docs/tour_connecting_boxes.md#share-a-type-between-boxes).
