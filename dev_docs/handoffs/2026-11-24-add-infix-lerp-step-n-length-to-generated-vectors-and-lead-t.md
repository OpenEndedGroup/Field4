## Proposed approach

- In the generator's operator model, add for Vector2f/3f/4f (and maybe d):
  - `infix fun V.lerp(t: Number): LerpFrom` with `infix fun LerpFrom.to(b: V): V` (returns a new vector), so `a lerp 0.5 to b` parses as `(a lerp 0.5) to b`. Note `to` collides with stdlib `Pair` `to`; a member/extension on the intermediate type wins, but check completion noise.
  - Same shape for `step`: result `a + normalize(b - a) * d`; if `|b-a| == 0` return a copy of a. Decide whether to clamp at b when d > |b-a|.
  - `val V.n: V` (new normalized copy) and `val V.length: Float` (check for clashes with existing `length()` member — a property and function of the same name are legal but confusing).
- Reorder the generated page: an "Ergonomic operators" + basic arithmetic section right after the intro, per-type reference tables after.

Alternative: hand-written extensions in `src/jvmMain/.../linalg` instead of the generator — faster, but splits the operator surface from the generated table.
